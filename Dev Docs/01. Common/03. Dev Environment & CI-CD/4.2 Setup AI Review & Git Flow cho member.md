# 4.2 Setup AI Review & Git Flow cho member

> AI Code Review tự động chạy trên mỗi Pull Request, đọc diff + source + mô tả PR, rồi
> comment trực tiếp các vấn đề lên PR trên Gitea. Tài liệu này gồm 2 phần:
> **(A) Setup repo** (dành cho lead/DevOps bật tính năng cho 1 project) và
> **(B) Git flow cho member** (dev làm việc hằng ngày cần biết).

Liên quan:
- Git flow nền tảng: `01. Common/01. Git/` (New BS Git Flow)
- Cơ chế validate code trong CI: `4.1 Sử dụng CI_CD để validate code cho member trong team`
- AI review chi tiết / đọc finding: `01. Common/06. AI Code Agent/AI Code Review.docx`

---

## Tổng quan nhanh

- **Chạy khi nào:** chỉ trên **build của Pull Request** (branch bắt đầu bằng `PR`). Push nhánh thường không trigger.
- **Làm gì:** review phần diff của PR, có quyền **đọc source** (read-only) để hiểu ngữ cảnh, đối chiếu với **mô tả PR**, rồi đăng review comment lên Gitea (comment inline tại đúng dòng + 1 summary).
- **Tính chất:** **advisory** — AI review **không tự làm PR đỏ/chặn merge**; nó báo vấn đề để member tự sửa. (Việc có gate hay không do pipeline caller quyết định.)
- **Bảo mật:** reviewer chạy read-only (chỉ `Read/Grep/Glob`), **không** có quyền chạy shell/ghi file.

## A. Setup repo (lead/DevOps)

Để bật AI review cho 1 project, cần 3 thứ:

### A.1. Credential token (bắt buộc)
Tạo Jenkins credential kiểu **Secret text**:
- **ID:** `claude_oauth_token`
- **Giá trị:** output của lệnh `claude setup-token`

> Token này cấp quyền gọi model. Coi như secret — xem phần *Lưu ý bảo mật* bên dưới.

### A.2. Chọn platform cho project (khuyến nghị)
Set biến môi trường **`REVIEW_SKILL`** cho job để reviewer nạp đúng bộ skill theo nền tảng:

| Project | `REVIEW_SKILL` | Skill được dùng |
|---|---|---|
| Magento | `magento` | `magento-review` + `magento-luma-review` / `magento-hyva-review` (tự chọn theo diff) |
| React Native / Mobile | `rn` | `rn` |

Không set → review generic (vẫn chạy, nhưng không áp rule theo platform). Bộ skill nằm ở repo riêng `bssdev03/ai_review_skills` (versioned, sửa bằng cách push repo đó, không đụng pipeline).

### A.3. (Tùy chọn) Chọn model
Set **`REVIEW_MODEL`** nếu muốn cố định model (vd `claude-opus-4-8`, `claude-sonnet-5`).
Không set → mặc định **`claude-opus-4-8`**.

### A.4. Gọi trong pipeline
`aiReviewCode()` được gọi ở **node level** trong flow PR của `runPipeline` (không lồng trong container multi-php — nó tự spin python container). Trả về **số lượng finding** (0 = sạch). Thông thường để **advisory**:

```groovy
// trong flow PR
def issues = aiReviewCode()   // chỉ báo cáo, không tự fail
// nếu muốn gate: if (issues > 0) { currentBuild.result = 'UNSTABLE' }
```

### A.5. PR template (bắt buộc có Description)
Repo phải có PR template với mục **Description (\*)**. Nếu member tạo PR mà **để trống / không điền** mục Description (còn nguyên placeholder), AI review sẽ **bỏ qua** và gửi **thông báo Skype** nhắc bổ sung mô tả. Xem template mẫu ở phần B.2.

## B. Git flow cho member (dev)

### B.1. Flow cơ bản
Theo đúng **New BS Git Flow** (xem `01. Common/01. Git/`):
1. Tạo nhánh từ base (`git checkout -b feature/xxx`).
2. Code → commit (message 1 dòng, rõ ràng).
3. Push nhánh lên Gitea.
4. **Tạo Pull Request** vào nhánh đích.

### B.2. Điền Description — **bắt buộc**
Khi mở PR, **phải điền mục Description**. Đây là context để AI đối chiếu code có làm đúng yêu cầu không. Template:

```markdown
### Description (*)
(Mô tả ngắn 1–2 câu: feature/bug này làm gì)

### Fixed Issues (if relevant)
1. ...

### Frontend Checklist (*)
 - [ ] Logic is in ViewModel, not in .phtml
 - [ ] No business logic in Alpine or template
 - [ ] Component is reusable
 - [ ] No new blocking JS

### Performance Checklist (*)
 - [ ] DOM optimized
 - [ ] Images optimized
 - [ ] Lazy loading applied where needed
 - [ ] Does not break Full Page Cache
 - [ ] No duplicated logic

### Self Test
 - [ ] Matches Figma / design
 - [ ] Tested on requirement
 - [ ] Tested with Guest / Logged in
```

> **Lưu ý:** chỉ **Description** là bắt buộc để AI review chạy. Các checklist (Frontend/Performance/Self Test) là tham khảo — thiếu cũng không sao, AI **không** báo lỗi vì thiếu checklist. Nhưng nếu diff **vi phạm** một mục đã tick thì AI có thể nhắc.
>
> Nếu Description để trống/placeholder → **AI review bị bỏ qua** + có noti Skype nhắc bổ sung. Bổ sung Description rồi push lại là được.

### B.3. AI review chạy & đọc kết quả
- Sau khi PR build, AI đăng **review comment** lên PR:
  - **Comment inline** đặt ngay dòng có vấn đề (nếu dòng nằm trong diff).
  - **Summary** tổng hợp ở cuối (cho các vấn đề nằm ngoài vùng diff).
- Mỗi finding gồm: **severity** (high/medium/low), **category**, mô tả **vấn đề** và **gợi ý** sửa (tiếng Việt, thuật ngữ giữ tiếng Anh).
- AI ưu tiên: **(1)** lỗ hổng security, **(2)** bug logic khó thấy (race condition, điều kiện sai, edge case...), **(3)** lỗi đúng/sai khác + **đối chiếu với Description** (code thiếu/sai so với yêu cầu đã mô tả).

### B.4. Sửa & push lại (incremental review)
- Member đọc finding → sửa → push commit mới.
- Lần review sau **không lặp lại** các finding đã báo trước đó (AI đọc các comment cũ để biết đã review gì).
- AI review là **advisory**: không tự chặn merge. Member/reviewer người vẫn chịu trách nhiệm quyết định merge.

## Lưu ý bảo mật

- Reviewer chạy **read-only** (`Read/Grep/Glob`), **chặn Bash/Write/network tool** → giảm rủi ro rò rỉ credential. **Không** nới quyền (vd bật Bash) chỉ để tiện — xem rủi ro prompt-injection trong `01. Common/08. Security`.
- Token `claude_oauth_token` và credential CI là secret: không in ra log, không nhét vào code/URL.

## Troubleshooting

| Hiện tượng | Nguyên nhân thường gặp |
|---|---|
| PR không có comment AI | Build không phải PR; hoặc diff rỗng; hoặc thiếu credential `claude_oauth_token` |
| Noti "PR thiếu Description" | Mục Description để trống / còn placeholder → điền mô tả rồi push lại |
| Review generic, không theo platform | Chưa set `REVIEW_SKILL` cho job |
| Comment đặt sai dòng | Hiếm — đã có bước verify lại line number; báo lead nếu còn lệch |
